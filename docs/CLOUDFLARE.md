## 보안 경계

- 공개 자산은 기존 69개 허용 목록과 404 문서만 배포. 관리자 화면, 녹음, DB, 모델, 로컬 설정 및 키 제외.
- `/api/sync`는 별도 256비트 키 및 고정 게시자 ID 필요. 키는 로컬 제외 파일과 Worker secret으로만 관리.
- 종료본 수신은 기존 공개 데이터 검증·내용 해시·리비전·요청 ID 재사용 검사 재사용. 진행 중인 회의록과 실시간 자료가 담긴 snapshot은 Cloudflare에서 거절.
- 완료본에는 AI 후보정된 공개 문장만 포함. 관리용 원문과 후보정 이력은 업로드하지 않음.
- D1은 바인딩된 매개변수 SQL과 원자적 조건부 생성·수정 사용. 외부에서 SQL, 저장 경로 또는 임의 URL 지정 불가.
- 실시간 중계는 GET 및 제한된 OPTIONS, 4개 경로만 허용. 쿠키·Authorization 전달 차단, 리디렉션 거절. VPC 대상은 127.0.0.1:4321로 고정.
- CSP, HSTS, 클릭재킹 방지 및 콘텐츠 유형 보호 적용. 와일드카드 Origin·인라인 스크립트 허용 없음.
- Wrangler 인증은 Windows 자격증명 저장소 사용. 상속된 기존 브릿지 토큰은 변경하지 않고 JC-LIVE CLI 프로세스에서만 제외.
- 새 배포 도구 의존성의 undici를 7.30.1로 고정. 전체 의존성 audit 0건. 이 패키지는 공개 Worker 코드에 포함되지 않는 개발 도구 의존성임.
- Tunnel 토큰은 `data/jc-live-tunnel.secret`에 저장하고 현재 Windows 사용자만 접근하도록 ACL 제한. 명령줄에는 토큰 대신 파일 경로만 전달.

## 무료 사용량과 제약

Workers Free, D1 무료 범위 및 무료 베타 Workers VPC 사용. Workers Paid, R2, 결제 등록, 유료 추가 기능 활성화 없음. 베타 종료 후 요금 정책은 재확인 대상.

| 항목 | 확인값 또는 계산 |
|---|---|
| D1 현재 저장량 | 공급자 조회 1.2MB |
| 최초 게시 | 종료본 7건 및 목록 2건, HTTP POST 9회 |
| 최초 게시 본문 | 압축 전 약 7.22MB, 실제 요청 본문 약 1.41MB. 청구 전송량과 다름 |
| 동일 자료 재게시 | 추가 POST 0회 확인 |
| 실시간 문장·후보정 | SQLite 이벤트 발생 시 즉시 전달 |
| 상태 정보 | SSE 연결에서 5초마다 전달 |
| 전체 자료 재확인 | Cloudflare 빌드에서 120초 간격, 무작위 분산 적용 |
| 요청 계산 예시 | 300명·6시간 기준 재확인 54,000회, 최초 snapshot·SSE 600회, 일정 조회 약 11,100회. 합계 약 65,700회 |

요청 계산은 사용자 조작, 과거 구간 조회, 회의록 조회, 재접속, 실패 재시도, 다른 Worker 사용량을 제외한 추정. 무료 Workers 하루 100,000회 및 호출별 CPU 10ms 한도 적용. 실제 동시 300명 인터넷 유지 시험 결과가 아님. D1 무료 DB당 500MB, 계정 총 5GB, 하루 읽기 500만 행·쓰기 10만 행 한도는 다른 프로젝트와 함께 고려.

D1 한 행 상한 때문에 압축 문서 1.9MB 초과는 게시 거절 후 로컬에 보존. 내용을 잘라 게시하지 않음. 대형 회의록은 추가 분할 저장 설계 또는 별도 승인된 저장소가 필요. PC·회선·터널 중단 중에는 새 실시간 내용이 전달되지 않으며 완료 회의록은 Cloudflare에서 열람 가능.

## 실행 명령

저장소 루트 PowerShell 기준. 인증값 출력 금지.

```powershell
# 현재와 같은 조회 전용 모드. GPU 모델 실행 없음.
./scripts/start-cloudflare.ps1 -Mode Viewer

# 엔진을 사용할 때 조회 전용 프로세스만 먼저 종료
./scripts/stop-cloudflare.ps1 -ViewerOnly
./scripts/start-cloudflare.ps1 -Mode Engine

# 종료 회의록 수동 게시. Cloudflare 대상만 전송.
./bin/node/node.exe scripts/publish-cloudflare-archives.mjs

# 최초 1회: 계정·D1·VPC ID를 넣을 로컬 배포 설정(git 제외) 만들기
Copy-Item cloudflare/wrangler.example.json cloudflare/wrangler.local.json
# account_id, d1_databases의 database_id, vpc_services의 service_id 값을 채워 저장

# Cloudflare 소스 빌드 및 배포
$env:JC_LIVE_DESKTOP_ORIGIN = 'https://jc-live.xgfox54.workers.dev'
./bin/node/node.exe cloudflare/build.mjs
./bin/node/node.exe scripts/cloudflare-cli.mjs deploy --dry-run
./bin/node/node.exe scripts/cloudflare-cli.mjs deploy

# 검증
./bin/node/node.exe --test test/*.test.mjs
./bin/node/node.exe scripts/verify-cloudflare.mjs
```

`start-cloudflare.ps1 -Mode Engine`은 기존 설정대로 방송 감지·수신·GPU 모델·후보정을 시작하므로 방송 시험 또는 운영 시간에 실행. 기존 Ollama 작업을 종료하는 명령은 포함하지 않음. 조회 서버는 전사 엔진을 대신하지 않음. 현재 스크립트는 재부팅 후 자동 시작 작업을 등록하지 않음.

`start-cloudflare.ps1`은 WMI(`Win32_Process.Create`)로 별도 실행기 프로세스를 만들고, 그 실행기가 엔진·조회 서버·터널을 시작함. 터미널이나 Codex 세션의 Windows 작업 개체(Job Object)에 서비스가 묶이지 않으므로 세션을 닫거나 Codex 앱이 재시작돼도 서비스가 유지됨. 실행 결과와 오류는 `data/cloudflare-start.log`에 기록하고 실행한 셸에도 표시함. `-Detached`는 실행기 내부용 인자임.

추가 배포 시 `cloudflare/package-lock.json` 기준 `npm ci --ignore-scripts` 사용. D1 스키마 변경은 새 마이그레이션을 추가하고 확인 후 적용. 기존 마이그레이션이나 운영 DB 삭제 금지.

## Vercel 병행 운영

기존 `cloudSyncFile` 유지, `cloudSyncFiles`에 Cloudflare용 비밀 설정 경로 추가. 두 대상 모두 `archive_only=true`. Vercel의 이전 실시간 전송 대기 요청은 삭제하지 않으며, 미확정 요청이 남아 있으면 자동 전환 게시 차단.

Vercel 재배포 가능 시 아래 환경값으로 기존 Linux 빌드 절차 적용:

```text
JC_LIVE_DESKTOP_ORIGIN=https://jc-live.xgfox54.workers.dev
```

Vercel 빌드가 CSP와 실시간 연결 설정을 함께 생성함. 실제 데스크톱 주소가 지정된 빌드는 두 공급자 모두 120초 재확인과 실시간 SSE 상태 전달을 사용. 기본 로컬 화면은 기존 설정 유지. 기존 Vercel 배포를 삭제·이전하거나 도메인을 교체하지 않음.
