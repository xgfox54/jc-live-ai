- 실시간 후보정과 방송별 일괄 후보정에 참고어 적용. 이름의 발음과 문맥이 맞을 때만 사용하고 원문에 없는 참석·발언 사실 추가 금지.

## 처리 조건

1. 모든 수집 세션 종료(서버 재시작으로 중단된 세션 포함), 전사 대기열과 화자 분석 완료 확인.
2. 수집 종료 판단: 영상 끝 도달(eof), 방송 종료 상태 확인, 또는 마지막 입력 후 10분 경과 중 하나. 수동 중지·시간 제한·연결 중단도 10분 경과 후 종료로 처리.
3. 실시간 1·2차 후보정 진행 중이면 대기. 숫자 검사·환각 필터로 보류·거부된 문장은 공개 대상이 아니므로 기다리지 않음. 검토 대상은 AI 후보정이 끝난 공개 문장.
4. 관리자가 저장한 2차 모델을 우선 사용하고, 없으면 1차 모델 사용. 자동 후보정 설정을 켠 일반 실행에서 15초마다 대상 확인.
5. 전체 회의에서 자기소개·발언 요청 근거 탐색 후, 모든 문장 묶음을 순서대로 AI 검토. 각 구간마다 인물과 근거 인용 검증.
6. 검토 중 원본이 바뀌면 결과 게시 중단. 전체 묶음 검토 완료 후 별도 이름 판정 저장.

누락·중단 기록이 있어도 수집된 부분은 검토. 검토 후 같은 방송에 새 입력이 들어오면 기존 결과 무효, 다시 종료된 뒤 재검토. `--manual` 실행은 자동 작업을 끔. 관리자 수동 실행도 위 조건을 우회하지 않음.

2026-10-23 변경: 이전 조건(정상 끝 도달 필수, 전체 문장 후보정 필수, 누락 기록 없음)은 실제 운영 회의 6건에서 한 번도 충족되지 않아 재검토가 실행되지 않음. 위 조건으로 완화.

## 이름 근거 (2026-10-23, grounded-segment-review-v4)

| 근거 | 적용 범위 |
|---|---|
| 의원 자기소개 ‘○○○ 의원입니다’ | 같은 화자 번호의 이후 발언, 5분 이내 |
| 공무원 자기소개 ‘직함 ○○○입니다’ | 같은 화자 번호의 이후 발언, 5분 이내. 세 글자 이름만 인정 |
| 발언 요청 ‘○○○ 의원님 질의해 주시기 바랍니다’ | 다음 발언부터 같은 화자 번호, 15분 이내 |
| 위원장 진행 문장(개의·상정·선포·질의 요청 등) | 그 문장이 있는 구간만 위원장 |

- 음성 인식 오류로 바뀐 의원 이름(예: 이장환 → 이정한)은 같은 성·같은 글자 수·자모 2개 이하 차이이며 가장 가까운 의원이 1명일 때만 연결.
- 공무원은 명단에 같은 직함이 있을 때만 비슷한 이름을 그 사람으로 연결. 다른 직함이면 들린 이름 그대로 사용.
- 화자 번호가 ‘여러 명’ 또는 ‘미확인’인 구간은 발언 시간 70% 이상을 차지한 번호를 사용.
- 다음 발언 요청, 위원장 진행 문장, 같은 화자 번호의 새 자기소개가 나오면 연결 종료.
- 규칙으로 후보가 정해진 구간만 AI에 보내 확인. AI는 후보 중 선택하거나 null만 반환.
- 한 묶음 응답이 두 번 실패하면 그 묶음은 미확인으로 두고 계속 진행. 모든 묶음 실패 시 결과 저장 없이 30분 후 재시도.
- 근거 방식이 바뀌면(REVIEW_METHOD) 기존 결과는 표시를 유지한 채 자동 재검토.

운영 회의 6건 결과(v3 기준, 이름 확정 구간/전체 공개 구간): 행정자치 54/358, 보건복지안전 73/320, 환경도시 28/358, 문화관광체육 45/346, 농수축 36/356, 2차 교육 32/217. 나머지는 근거 부족으로 ‘발언자 미확인’. 사람이 원음과 대조한 정확도 검증은 미실시.

## 이름 판정과 표시

- 화자 번호 전체를 한 사람으로 바꾸지 않고 구간별 이름 판정 저장.
- 같은 번호의 다른 사람을 분리하고 다른 번호의 같은 이름을 발언 내용 정리에서 통합.
- 자기소개·발언 요청의 정확한 본문 인용 필수. 명단 포함, 단순 이름 언급, 모델의 확신만으로 이름 지정 금지.
- 근거 구간 이후 연속성 확인 범위는 같은 세션·시간축의 최대 12개 구간 및 120초. 새로운 자기소개·발언 요청, 겹친 발언, 번호·분석 범위 변경 시 근거 승계 제한. 이 범위를 벗어난 발언은 이름이 누락될 수 있음.
- 원음의 실제 신원과 일치하는지 최종 확인 필요. 텍스트 검토만으로 모든 발언자를 식별할 수 없음.
- 실시간에는 참여자 번호 표시. 종료 후에는 확인된 이름 또는 ‘발언자 미확인’ 표시. 의원과 공무원 발언 구분.
- 원문·후보정 문장·화자 분석 결과는 보존. 공개 JSON과 Markdown에는 후보정 완료 문장만 포함.

## 관리자 조작

‘기록·AI 회의록’에서 방송 선택 후 ‘전체 발언자 재검토’ 사용. 준비 상태·완료 묶음 수·미확인 구간 수 표시. ‘발언자 검토 중지’로 요청 취소. 실패·관리자 중지 상태는 같은 원본에 자동 재시도하지 않으며 관리자가 재실행 가능.

인증이 필요한 경로:

```text
GET /api/admin/workspace/final-speakers?broadcast=<방송 ID>
POST /api/admin/workspace/final-speakers
POST /api/admin/workspace/pause-final-speakers
```

POST 본문: `{"broadcast_id":"방송 ID"}`. 기존 관리자 인증과 출처 검사를 그대로 적용.

- 2026-10-22 회귀시험: 총 146개, 통과 144개, 실패 0개, 건너뜀 2개. 건너뛴 항목은 SenseVoice 음원 시험과 별도 환경 변수가 필요한 네이티브 모델 로더 시험.

- 실제 브라우저: 390·820·1440px, 밝은색·어두운색 환경에서 이름·미확인 표시, 키보드 펼치기, 가로 넘침 확인. 기존 화면은 두 색상 환경 모두 같은 밝은색 디자인 사용. 이름 판정 표시는 합성 시험 결과를 요청 응답에 주입해 확인.
- 로컬 기존 기록 14건은 끝 도달 미확인으로 판정. 운영 회의록에 이름을 추정해서 일괄 입력하지 않음.
- 실제 회의 전체 재처리 정확도, 8개 방송과 종료 검토 통합 부하, Lighthouse 점수 측정은 미실시.

## 중지·복구

- 전체 서비스 정상 중지: `bin/node/node.exe scripts/stop-live.mjs config.local.json`.
- 자동 동작 없이 복구: `bin/node/node.exe src/main.mjs config.local.json --manual`.
- 일반 자동 동작: `bin/node/node.exe src/main.mjs config.local.json`. 기존 탐색·클라우드 설정도 함께 적용되므로 운영 설정 확인 후 사용.
- 검토 결과는 `review_state`의 `final-speakers:<방송 ID>`, 진행 상태는 `speaker-job:<방송 ID>`에 별도 저장. 원문·기존 화자 정보 덮어쓰기 없음.
- 롤백 시 이번 기능의 코드 변경만 이전 상태로 복원. DB·원음·후보정 이력 삭제 금지. 이전 코드는 새 검토 레코드를 사용하지 않음.
- 이번 작업은 로컬 반영 및 공개 웹 자산 빌드까지 수행. Git 커밋·GitLab 업로드·Vercel 배포는 미실시.
