# 데스크탑 우선·랩탑 대기 운영

데스크탑 전사 엔진이 멈추면 랩탑이 대신 전사하고, 데스크탑이 돌아오면 데스크탑이 다시 맡는 구조. 2026-11-11 데스크탑 전원 중단 때 랩탑에서 구성·배포한 기능을 2026-11-13 데스크탑 저장소에 통합.

## 구성

| 구성요소 | 위치 | 역할 |
|---|---|---|
| 우선순위 중계 | `cloudflare/priority-routing.mjs`, `cloudflare/live-proxy.mjs` | 시청자 요청마다 데스크탑 상태 조회(`/api/viewer/status?probe=1`)와 실제 요청을 함께 전송(2026-11-21부터). 데스크탑 엔진이 실행 중이면 데스크탑 응답 전달. 엔진이 멈췄거나 응답하지 않으면 데스크탑 요청을 취소하고 랩탑 터널로 중계. 응답 헤더 `X-JC-Active-Processor`에 처리 기기 표시 |
| 대기 확인 경로 | `/api/failover` | 랩탑 키(`X-JC-Laptop-Key`)가 있는 GET 요청에만 데스크탑 상태 응답 |
| 전사 인계 저장 | `cloudflare/handoff.mjs`, `/api/handoff`, D1 `handoff_progress`·`handoff_rows` | 영상별 처리 완료 위치와 전사 문장 공유. 데스크탑은 게시 키, 랩탑은 랩탑 키로 인증 |
| 엔진 인계 | `src/handoff.mjs` 외 7개 파일 | 시작할 때 공유 위치 10초 앞에서 수집 재개, 이미 처리한 구간 저장 생략, 60초마다 위치·문장 업로드(요청당 최대 60문장, 2026-11-25부터. 이전에는 15초마다 30문장) |
| 대기 임대 | `src/main.mjs`(`standbyLeaseFile`) | 유효한 임대가 없으면 엔진 시작 거부, 임대가 끝나면 수집부터 중지 |
| 랩탑 대기 실행 | `scripts/standby/` | 대기 제어기, 읽기 전용 중계 게이트, 임시 터널 주소 갱신, 창 없는 예약 작업 실행기 |
| 음성 감지 게이트 | `src/acoustic-vad.mjs`, `worker/speech_gate.py`(`acousticVad`) | 화자 분리가 없는 랩탑에서 Silero VAD로 무음 판정 |

## 처리 흐름

1. 랩탑 대기 제어기가 `/api/failover` 조회. 평소 60초마다, 데스크탑 무응답이 확인된 뒤와 랩탑이 전사하는 동안은 15초마다 조회(2026-11-25부터. 이전에는 항상 15초).
2. 데스크탑 무응답이 60초 이상 이어지면 랩탑이 25초짜리 임대를 기록하고 엔진 시작. 상태를 알 수 없는 응답은 중단으로 보지 않음.
3. 시청자 요청은 Worker가 데스크탑 상태를 확인한 뒤 랩탑 게이트로 중계. 게이트는 랩탑 키와 유효한 임대를 모두 확인.
4. 데스크탑이 다시 응답하면 다음 확인(최대 약 15초 뒤)에서 랩탑 임대 종료. 게이트가 2초 안에 열린 연결을 끊고, 랩탑 엔진은 수집을 먼저 멈춘 뒤 종료. 시청자 화면은 다시 연결하면서 데스크탑으로 이동.

데스크탑이 멈춘 뒤 첫 무응답 확인까지 최대 60초가 걸리므로, 랩탑 전사 시작은 데스크탑 중단 뒤 60~120초 사이임(이전 60~75초).
5. 수집 PC가 바뀌면 새 PC가 공유 위치를 읽어 영상 시간 기준으로 이어서 전사.

랩탑이 처리하는 동안의 실시간 이벤트 연결은 30초마다 끊고 다시 연결해 복귀한 데스크탑으로 넘어감. 데스크탑 처리 중에는 연결 유지.

## 전사 인계 기준

- 위치 기준: YouTube 원본 타임스탬프(PTS)로 계산한 영상 시간. 녹음 시작 시각·수신 시각 미사용.
- 재개 위치: 공유 위치와 로컬 세션 위치 중 큰 값의 10초 앞. HLS 재생 목록 범위 밖이면 다시보기 처음부터 받고 앞부분 잘라냄.
- 중복 방지: 재개 위치 이전에 끝나는 구간 저장 생략. 공유 위치는 뒤로 가지 않음(D1 조건부 갱신).
- 표시 시간: 인계 뒤 구간은 영상 시간으로 표시(`video_offset_ms`).
- 조건: 같은 YouTube 영상, 세션 중 누락 없음(`total_gap_s` 0), 원본 시계 연속. 조건이 맞지 않으면 위치 미공유.

## 설정

데스크탑 `config.local.json`(현재 적용):

~~~json
{ "handoffFile": "data/handoff.json" }
~~~

`data/handoff.json`(git 제외, 비밀 값은 별도 파일):

~~~json
{ "endpoint": "https://jc-live.xgfox54.workers.dev/api/handoff", "secretFile": "<게시 키가 든 비밀 설정 파일>", "secretJson": true, "processor": "desktop" }
~~~

랩탑 `config.local.json` 추가 항목:

~~~json
{
  "handoffFile": "data/handoff.json",
  "standbyLeaseFile": "data/standby/state.json",
  "liveDiarization": false,
  "speechGate": true,
  "acousticVad": { "python": "<Python 실행 파일>", "model": "<silero_vad.onnx 경로>", "dependencies": "<numpy·onnxruntime 설치 폴더>" }
}
~~~

- 랩탑 설정에는 `cloudSyncFile`·`cloudSyncFiles`·`desktopLive` 미설정. 완료 회의록 게시는 데스크탑 담당이고 4321 포트는 게이트가 사용.
- 랩탑 `handoff.json`은 `processor`를 `laptop`으로, 비밀 파일은 게이트 키 파일로 지정.
- Worker 바인딩: `JC_LAPTOP_URL`(일반 변수, 임시 터널 주소), `JC_LAPTOP_SECRET`(비밀, 게이트 키), `JC_SYNC_SECRET`(비밀, 기존 게시 키). `cloudflare/wrangler.example.json`(데스크탑은 ID를 채운 `wrangler.local.json` 사용)의 `"keep_vars": true` 때문에 데스크탑에서 다시 배포해도 `JC_LAPTOP_URL` 유지. Wrangler는 설정 파일에 없는 일반 변수를 배포 때 삭제하고 비밀은 유지함.
- 비밀 값은 `wrangler secret put` 입력창으로만 등록. 명령 인자·로그·문서에 기록 금지.

## 랩탑 실행

| 단계 | 명령·설정 |
|---|---|
| 게이트 키 생성 | `node scripts/standby/live-gateway.mjs config.local.json` 최초 실행 때 `data/standby/gateway.secret` 생성. 같은 값을 Worker 비밀 `JC_LAPTOP_SECRET`으로 등록 |
| 환경 변수 | 랩탑 사용자 환경에 `CLOUDFLARE_ACCOUNT_ID`, Workers 스크립트 편집 권한의 `CLOUDFLARE_API_TOKEN` 설정. 터널 주소 갱신에만 사용 |
| 실행기 컴파일 | `csc.exe /nologo /target:winexe /out:scripts\standby\StandbyLauncher.exe scripts\standby\StandbyLauncher.cs`(.NET Framework 4 컴파일러, 실행 파일은 git 제외) |
| 예약 작업 | 이름 `JC-LIVE Laptop Standby`, 1분 간격, `StandbyLauncher.exe` 실행. 실행기가 `ensure-standby.ps1`을 창 없이 실행 |
| 유지 대상 | `ensure-standby.ps1`이 게이트, 대기 제어기, cloudflared 임시 터널(127.0.0.1:4321)을 확인해 없으면 시작. 새 터널 주소가 나오면 `update-tunnel-binding.mjs`로 `JC_LAPTOP_URL` 갱신 |
| 상태·기록 | `data/standby/`(임대 파일, 키, 프로세스·엔진·터널 기록) |

랩탑에서 실제 실행 중인 대기 스크립트는 2026-11-11 랩탑 작업 폴더의 원본. 저장소 판은 같은 동작을 저장소 경로 기준으로 정리하고, 11-11 세션 1건을 숨기던 고정 필터를 뺀 판. 저장소 판으로 바꿔 실행한 시험은 미실시.

## 랩탑 음성 감지 게이트

- 무음 조건: 20ms 구간 표준편차 12 이하이고 최대 진폭 48 이하인 잡음 수준, Silero VAD 최대 확률 0.15 미만. 확률 0.5 이상이면 발언, 그 사이는 판정 보류. 화자 분리 결과에 발언이 있으면 화자 분리 결과 우선.
- 실행: 랩탑 Python(numpy, onnxruntime)에서 `worker/speech_gate.py` 상주. 검출기가 응답하지 않으면 판정 보류로 처리해 전사 계속.
- 데스크탑: 미설정. 데스크탑은 Nemotron 화자 분리와 2026-11-11 적용한 -65dBFS 거의 무음 기준 사용.
- 랩탑 결과(랩탑 세션 보고): 방송 전 '감사합니다' 오인식 334건 공개 제외, 수정 후 방송 대기 3분 7초 동안 잘못된 자막 0건, 실제 본회의 발언을 원래 음량과 10분의 1 음량에서 모두 발언으로 판정.

## 2026-11-13 데스크탑 통합

- 랩탑이 운영 Worker 묶음 파일을 직접 고쳐 배포한 내용을 `cloudflare/` 소스로 옮김. 통합 전에는 데스크탑에서 다시 배포하면 우선순위 중계, 인계 경로, 복구 회의록 보호가 사라지는 상태.
- 데스크탑 작업 폴더의 미커밋 엔진 인계 변경(랩탑 세션이 11-12 적용, 데스크탑 엔진 실행 중)을 시험과 함께 커밋.
- 랩탑 판과 다르게 정한 2가지:
  - 실시간 이벤트 연결 30초 제한을 랩탑 처리 중에만 적용. 랩탑 Worker는 데스크탑 처리 중에도 30초마다 연결을 끊어, 시청자 1명이 시간당 약 116회 Worker를 호출(계산값). 기존 설계는 회의당 약 1회. 300명이 6시간 시청하면 하루 무료 한도(10만 회)를 넘을 수 있는 수준.
  - 보관 저장소 감싸기 객체를 DB마다 한 번만 생성. 요청마다 새로 만들면 공개 회의록 해석 결과 캐시가 적중하지 않음.
- 2026-11-13 07:46 데스크탑 소스 Worker 배포(`1ded5377`, 직전 `eb901621`)로 위 2가지 적용.
- 저장소에 넣지 않은 랩탑 작업: Rust 작업자 요청 한도 상향(600KB에서 1.5MB, 다시보기 일괄 전사 전용), 회의 ID가 고정된 일회성 복구 스크립트(`backfill-*`), 임시 복구 게시 경로(11-12 12:00 만료). 기록은 랩탑 작업 폴더에 보존.
