# AI 후보정·장시간 운영

데스크톱 복원 후 추가한 AI 구조화 회의록·자동 적용 선택·연결 보관·모델 관리 기능은 [기능 적용 결과](FEATURE_PARITY.md) 참조. 아래 검증 기록은 랩탑 작업 당시 결과임.

## 관리자 설정

1. 로컬 관리자 페이지의 ‘AI 후보정·단어장’ 선택.
2. 연결 방식 선택. OpenCodex는 기본 주소 `http://127.0.0.1:10100/v1` 사용. 다른 OpenAI 호환 프록시는 운영 중인 API 기본 주소 입력. 외부 주소는 HTTPS 필요.
3. 프록시에서 인증을 요구하는 경우 해당 키 입력. 빈칸은 저장된 키 유지, 주소 변경은 기존 키 삭제. 저장된 키는 화면·공개 API에 반환하지 않음.
4. AI 설정 저장 후 ‘연결 모델 확인’으로 저장된 연결의 목록 확인. 모델 ID 직접 입력 가능.
5. 방송 기록과 분야 선택, 추가 참고어 입력 후 단어장 저장.
6. 후보 생성 후 원문과 후보 대조. 선택 적용 또는 경고 없는 후보 일괄 적용 수행. 숫자·길이 경고 후보는 원음 확인 체크 후 개별 적용.

## 처리 방식

| 항목 | 동작 |
|---|---|
| 원문·직접 수정 | 원문 별도 보존. 버전 변경 시 이전 후보 적용 차단. 직접 수정 덮어쓰기 차단 |
| 분야 | 의회, 감사, 예산, 조례·자치, 제주, 복지·보건·안전, 환경·농업·해양, 관광·문화·체육, 도시·교통·건설, 경제·일자리, 교육 |
| 참고어 | 직접 입력과 분야별 대표어 우선, 중복 제거 후 최대 3,000자. 단어 중간 자르기 없음. 제외 수 화면 표시 |
| 음성 인식 | 기존 인식 참고어 600자와 분리. 분야 단어장은 AI 후보정에만 전달 |
| 입력 분할 | 문장별 900자 이하 부분 구간. 요청당 최대 4개·합계 1,800자. 응답 ID·전체 문장 수 검증 |
| 자동 생성 | 프록시는 수집 중에도 처리. 방송별 20문장씩 순환. 로컬 Ollama는 모든 녹음·전사 종료 후 처리 |
| 적용 | 기본 수동 적용. 선택 시 경고 없는 후보 자동 적용. 반영된 전사문·회의록은 기존 공개 전송 주기에 게시 |
| 실패·중단 | 원문과 기존 후보 보존. 서버 재시작·오류·사용자 중단 작업은 직접 재시작 |
| 로컬 자원 | Ollama 요청은 CPU 2스레드·GPU 사용 안 함. 프록시 처리는 해당 서버에서 수행 |
| 키 보관 | SQLite 안에 AES-256-GCM 암호문 저장. 서버 인증키에서 암호화 키 파생, 연결 주소 결합 |

프록시 후보정은 전사문과 참고어를 선택한 서버에 전송하는 방식. 프록시의 실제 모델 실행 위치·이용 조건은 해당 연결 설정에 따름. 비공개 회의 자료 입력 전 운영자의 연결 대상 확인 필요.

## 방송당 10시간

| 항목 | 용량·범위 |
|---|---|
| 저장 형식 | 16 kHz·단일 채널·16비트 PCM, 초당 32,000바이트 |
| 10시간 원음 | 1,152,000,000바이트, 약 1.15 GB |
| 기본 세션 한도 | 1,382,400,000바이트, 12시간 |
| 8개·각 10시간 | 원음 합계 9,216,000,000바이트, 약 9.22 GB. DB·회의록·임시 파일 공간 별도 |
| 전사 | 10시간을 통째로 모델에 넣지 않고 5초·10초 구간으로 처리. 장시간 세션 전체 종료 시간 제한 없음 |
| 공개 게시 | 긴 회의록·전사문 압축 전송·보관, 전체 구간 페이지 조회·내려받기 |

저장 한도는 세션별 적용. 기존 설정에 작은 한도가 저장되어 있으면 세부 설정에서 1,382.4 MB 이상으로 변경 필요. 연결 중단·절전·저장 공간 부족은 별도 실패 원인. 제공자의 시작 부분 보관 범위를 넘는 음성 복구는 보장하지 않음.

## 모델 선택 근거

현재 전사는 `whisper.cpp` 기반 Rust 워커와 Whisper small Q5_1 양자화 모델, Vulkan GPU 사용. 이식된 실행 자산을 유지하고 랩탑의 8개 입력 처리량을 검증한 기준 구성. 한국어 정확도가 가장 높다는 비교 결과에 따른 선택은 아님.

기존 시험에서 8개 합성 음성 480초를 49.799초에 처리하고, 8개 입력을 각 150초간 실시간 속도로 전달한 시험에서 오류·누락 0건 확인. 실제 의회 발언의 정답 대비 정확도 및 8개 실방송 10시간 안정성은 미검증.

`faster-whisper`는 CTranslate2를 사용하는 Whisper 실행 구현. small 또는 large 계열 모델 실행과 INT8 양자화·배치 처리 지원. 현재 목적에 사용할 수 있으나, 이 랩탑에서 whisper.cpp와 동일 음원·동일 모델·동일 탐색 조건으로 비교하지 않았으므로 성능 우열 미확인. NVIDIA GPU 실행에는 해당 버전에 맞는 CUDA·cuDNN 환경 필요.

근거: [faster-whisper 공식 문서](https://github.com/SYSTRAN/faster-whisper), [whisper.cpp 공식 문서](https://github.com/ggml-org/whisper.cpp).

## 2026-10-20 검증 범위

- 자동 테스트 74개 통과: 후보 검증·원문 보존·수정 충돌·암호화 키·프록시·10시간 전사문 게시 포함.
- 실제 OpenCodex 프록시·`gpt-6-luna`·복지 단어장으로 후보 생성 확인. 합성 문장 1개, 3.723초. 숫자 100만 원과 원문 보존.
- 실제 FFmpeg로 10시간 무음 입력을 가속 수집. 36,000초·1,152,000,000바이트 저장, 3,600개 무음 구간 처리, 누락·오류 0건.
- 긴 전사문 3,600개 구간의 압축 게시·전체 페이지 조회·JSON 내려받기 검증.
- 무음 가속 시험은 10시간 실제 경과·실방송·Whisper 추론 부하 시험과 다름.
- 8개 실방송·프록시 후보정 동시 처리의 장시간 처리량과 정확도는 미검증.
