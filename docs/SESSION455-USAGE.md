# 제455회 방송 내역 기준 사용량 재산정

확인일: 2026-10-25. 앞선 월 176시간·8방송 지속 가정과 실제 제455회 방송량을 구분하기 위한 재산정. 운영 설정·배포 변경 없음.

## 이전 가정의 수정

이전 176시간은 실제 확인한 방송 시간이 아닌 용량 검산용 입력값. 8방송이 176시간 내내 가동된 것으로 보면 합산 1,408채널·시간이며 이번 확인값 129.7채널·시간의 약 10.9배. 사이트 운영 시간을 비교하면 176시간에서 추정 45.7시간으로 약 74% 감소.

300명이라는 서비스 접속 목표만으로 방송 중 평균 동시 접속자 300명을 전제할 수 없음. 평균 동시 접속, 최대 순간 접속, 회기 전체 방문자 수를 구분. 실제 이용자 로그가 없으므로 아래 표는 평균 동시 접속 시나리오.

## 현재 게시 방식의 예상 요청

소스의 기본 10초 청크와 비교하기 위해 앞선 산정과 동일하게 내용 변경 기회를 10초마다 한 번으로 가정. 음성이 없거나 내용이 같으면 게시 생략. 실제 초안·후보정 이벤트 간격, 회의록 재편집, 재시도는 별도이므로 이 숫자는 실제 청구량이나 수학적 상·하한이 아님.

| 항목 | 이번 회기 기준 계산 |
|---|---:|
| 방송 구간의 통합 snapshot 변경 기회 | 16,471회 |
| 5분 아카이브, 처음·마지막 저장 포함 | 1,634회 |
| 시간대가 같은 목록 갱신을 합친 추가 기회 | 609회 |
| 목록 갱신이 실시간 snapshot과 전부 겹치는 가정 | 합계 18,106회 |
| 목록 갱신이 별도 묶음으로 발생하는 가정 | 합계 18,715회 |
| 각 아카이브마다 별도 목록 갱신 가정 | 합계 19,740회 |

앞선 82,369회보다 크게 감소. 이 가정의 현재 실시간 Blob 저장 방식은 [무료 Advanced 포함량 2,000회](https://vercel.com/docs/vercel-blob/usage-and-pricing)를 여전히 초과. 정숙 시간 비율과 실제 공개 변경 횟수는 영상 길이만으로 확정 불가. 한도를 정확히 예측하려면 로컬 게시 계측의 변경·초안·후보정·아카이브 시도를 측정해야 함.

전사 확정 이후 인덱스·화자명·최종 요약 갱신 및 종료 후 대기열 배출은 계산에서 제외. 유휴 재전송은 개선 후 0회로 계산. 초기 snapshot 1회 포함. 원본 녹음 시간의 비용을 Vercel GPU 비용으로 계산한 것이 아님.

| 방송 중 평균 동시 접속자 | 45.7시간·5초 조회의 브라우저 요청 |
|---|---:|
| 1명 | 약 3.3만회 |
| 10명 | 약 32.9만회 |
| 20명 | 약 65.9만회 |
| 50명 | 약 164.7만회 |
| 100명 | 약 329.3만회 |
| 300명 | 약 987.9만회 |

회기 전체 방문자 300명이 각각 1시간만 시청하면 약 21.6만회. 이는 300명이 계속 동시 시청하는 경우와 다름. [CDN 무료 포함량 100만회](https://vercel.com/docs/plans/hobby)와 비교할 때 평균 10~20명의 브라우저 조회는 단독으로 포함량 이내지만, 게시 POST·Blob 접근·정적 파일·검색·방송 외 접속까지 포함한 무료 운영 보장은 아님. 실제 캐시 HIT와 함수·Simple Operations 사용량도 별도 확인 필요.

전송량은 평균 응답 크기와 304 비율에 의존. 예를 들어 응답 20KB, 304 비율 50%라면 평균 20명은 약 6.59GB, 평균 300명은 약 98.79GB의 브라우저 본문. 운영 측정치가 아닌 예시이며 Blob 전송·헤더·자산·다른 API는 별도. 이번 재산정에서 8개 전체 텍스트 스트레스 응답 크기를 실제 시청자 응답으로 적용하지 않음.

## 전사는 어디서 실행하는가

| 위치 | 소스에서 확인한 역할 |
|---|---|
| 데스크톱 `src/main.mjs`, `src/engine.mjs` | 방송 음성 수신, 로컬 Whisper 워커 실행, GPU 전사, 방송별 작업 큐·화자분리 |
| 데스크톱 `src/server.mjs` | AI 후보정과 회의록 처리 조정. 설정된 로컬/프록시 AI를 호출하며 Vercel 함수로 이전하지 않음 |
| 데스크톱 `src/cloud-publisher.mjs` | 공개 검증된 텍스트·메타데이터·회의록 JSON을 HTTPS 전송 |
| Vercel `web/deployment/handler.mjs` | /api/sync 인증·저장, /api/viewer 조회·전달 |
| 비공개 Blob | 공개 화면에 보일 텍스트 사본 저장 |
| 이용자 브라우저 | 전사문 표시, 공식 영상 플레이어 또는 공식 영상 링크 이용 |

현재 로컬 설정은 `models/ggml-large-v3-turbo-q8_0.bin`, GPU, 10초 청크, altRecognizer false. 값 확인만 수행했으며 모델 실행·프로세스 재시작 없음. Vercel 웹 패키지는 Blob SDK만 의존하며 모델·GPU 워커·원음 저장 경로는 배포 대상에서 제외. 운영 사이트가 제한되어 이번에 배포된 함수 실행 자체를 재검증하지는 않았음.

데스크톱에서 전사하는 원래 계획은 유지. 화면 제공을 위해 구현한 지속적인 Blob 갱신과 API 폴링이 무료 포함량을 사용함. Vercel에서 음성 전사를 실행하는 구조는 아님.

## 이 방송량에 맞는 다음 설계

실시간 텍스트를 데스크톱의 공개 읽기 전용 경로에서 전달하고 Vercel에는 화면·완료 회의록만 두면, 이번 50건의 최종 회의록 저장은 기본 50회, 각 목록 갱신까지 단순 합산하면 100회. 이는 재편집·재시도·스냅샷 쓰기를 별도로 계산한 기초값이며 공급자 전체 무료 운영을 보장하지 않음.

따라서 제455회 방송량을 기준으로 원래 분담을 더 엄격히 적용한 구조의 무료 가능성은 추가 검토할 가치가 있음. 기존 Blob 실시간 갱신 방식의 한도 초과와 서비스 자체의 무료 운영 불가능을 동일하게 단정하지 않음. 데스크톱 공개 연결의 TLS·읽기 전용 인증·요청 제한·동시 300명 용량·PC/회선 장애 대응은 승인 후 검증 필요. 이번에 신규 서비스·터널·포트·DNS는 설정하지 않음.

## 재현과 증거

```powershell
& ./bin/node/node.exe reports/session455/collect.mjs
& ./bin/node/node.exe reports/session455/calculate.mjs
```

- `reports/session455/records.json`: 공식 상세 출처, 영상 길이, 재생목록 URL·해시.
- `reports/session455/calculation.json`: 날짜별·위원회별 합산과 모든 시나리오.
- `reports/session455/broadcasts.csv`: 50개 방송 목록.
- 목록·상세 HTML·m3u8은 재현용 로컬 증거. reports는 기존 Git 제외 대상이며 인계 시 별도 보관 필요.
- collector는 현재 저장된 공개 자료를 재사용. 새 시점의 사실 확인에는 별도 출력 폴더에서 다시 조회해야 함.
