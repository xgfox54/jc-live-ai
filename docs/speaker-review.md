# 종료 후 발언자 확인

## 처리 순서

1. 영상 수집·전사·문장 후보정 종료 확인. 수동 중지 기록은 마지막 입력 후 10분 대기.
2. 저장 원음 전체에 CPU 화자 분리 실행. 실시간 Nemotron 번호와 별도의 음성 그룹 생성. 최종 인원은 8명으로 고정하지 않음.
3. 자기소개·진행 발언·명시적 발언 요청으로 이름 후보 생성. 실시간 화자 번호로 연결된 기존 문장 근거는 유지. 종료 후 음성 그룹이 다른 이름을 제안해도 기존 이름을 자동 교체하지 않고 관리자 확인 대상으로 기록. 회의 날짜와 회의명이 일치하는 공식 기록 및 관리자가 확인한 참석자 명단 우선. 과거 명단·단어장은 참고 후보로 구분.
4. 기존 관리자 후보정 모델로 후보 수락·보류 판단. 같은 원문에서 이미 승인한 결과도 현재 근거 조건을 다시 검사한 뒤 재사용.
5. 단독 발언 음성 특징으로 미확인 구간 추가 비교. 같은 회의의 서로 다른 근거 구간 2개 이상 필요. 두 기준 음성과의 평균 유사도 0.8 이상, 다른 이름과의 차이 0.12 이상일 때만 연결. 서로 다른 이름이 경합하거나 화자가 바뀌는 구간은 보류.
6. 구간별 이름 결과를 별도로 저장하고 회의록에 반영. 원문·후보정 문장·실시간 화자 번호는 보존.

무음·단독 발언 3초 미만·음성 우세 비율 90% 미만 구간은 음성 비교에서 제외. 구간 내 교대·겹침이 있으면 전체 문장을 한 사람으로 자동 지정하지 않음. 음성 유사도는 신원 확인 확률이 아니며 수치는 한국어 정답 자료에 맞춰 보정하지 않은 초기 기준임.

## 관리자 사용

로컬 `/admin.html`의 ‘기록·AI 회의록’에서 방송 기록 선택.

- ‘전체 발언자 재검토’: 종료 후 전체 원음 재분석과 이름 검토 실행. ‘발언자 검토 중지’로 중단. 자동 후보정이 켜진 일반 모드에서는 종료 후 자동 실행.
- ‘발언자 원음 확인과 이름 지정’: 미확인 발언 검색, 원음 듣기, 이름·의원/공무원 구분 입력.
- ‘같은 목소리의 구간 검토’: 동일 음성 그룹이며 유사도 0.86 이상인 구간을 미리보기. 다른 이름이 이미 확인된 구간과 관리자가 미확인으로 지정한 구간은 확산 대상에서 제외. 잘못 묶인 구간은 체크 해제 후 저장. 분석되지 않은 구간은 ‘선택한 구간만’ 사용.
- ‘직전 이름 변경 되돌리기’: 직전 변경 이전의 상태를 새 버전으로 저장. 기존 이력 삭제 없음. 한 구간의 잘못된 이름은 해당 구간만 다시 지정.
- 같은 목소리 미리보기는 한 번에 최대 200구간. 저장 후 남은 구간을 이어서 확인. 미리보기 이후 선택한 문장이 수정되면 다시 확인해야 함.
- ‘회의 당시 참석자 명단과 근거’: 각 줄에 `이름 | 의원 또는 공무원 또는 기타 | 직책 | YYYY-MM-DD | 확인 자료 주소 또는 문서명` 입력. 회의 날짜가 등록되어 있으면 같은 날짜만 허용. 저장 후 전체 발언자 재검토 실행.

동시 수정·문장 변경·분석 변경은 저장을 거부하므로 목록과 적용 대상을 다시 확인해야 함. 관리자 접근키, 음성 특징, 원음 경로는 공개 API와 Vercel 자산에 포함하지 않음.

## 설치와 실행

Windows x64, CPython 3.14, uv 필요. 별도 Python 환경이며 Whisper·Nemotron·Ollama 설정은 변경하지 않음.

```powershell
& ./bin/node/node.exe scripts/setup-speaker-review.mjs
& ./bin/node/node.exe scripts/analyze-speakers.mjs <broadcast_id> config.local.json
& ./bin/node/node.exe --test test/*.test.mjs
```

설치 명령은 실행할 때만 공식 배포처에서 모델과 해시를 고정한 패키지를 내려받음. 서비스 시작 중 자동 다운로드 없음. `analyze-speakers.mjs`는 원음 분석 캐시만 저장하며 수집·AI 호출·원문 수정·외부 게시 없음.

| 설정 | 기본값 |
|---|---|
| `speakerReview` | `true` |
| `speakerReviewPython` | `bin/speaker-review/venv/Scripts/python.exe` |
| `speakerReviewDirectory` | `bin/speaker-review` |
| `alignmentPython` | 미설정. `speakerReviewPython`이 있으면 그 Python, 없으면 `diarizationPython` 사용. 영상 시간 대조 스크립트에 numpy 필요 |
| 실행 장치·스레드 | CPU, 2개 |
| 화자 그룹 수 | 자동 결정 |
| 처리 상한 | 세션당 6시간, 작업당 2시간 |

모델 출처·라이선스·SHA-256은 [manifest.json](../licenses/speaker-review/manifest.json)에 기록. 임베딩은 목소리를 비교하기 위한 수치 배열이며 이 구현은 해당 회의 안에서만 사용. 한국어 화자 정답 비교는 별도 시험 대상.

## 장애·중지·복원

- 새 수집 시작: 2초 간격으로 확인해 이 분석 작업의 프로세스만 종료. 다른 Ollama 작업은 조회·종료하지 않음.
- 모델 미구성·원음 미확보: 해당 상태를 표시하고 기존 문장 근거 검토 유지. 시간축이 재시작된 세션은 임의로 원음과 연결하지 않음.
- 실행 실패·중지: 이전 이름 결과 보존. 미완료 분석은 저장하지 않음. 다음 실행에서 원음 전체 재분석. 완료한 음성 특징은 원음 해시·원문 버전이 같으면 재사용.
- 새 발언자 재검토가 완료되면 이전 자동 판정 결과도 `final-speakers-history` 항목으로 보존. 공식 명단 자료가 갱신되면 자동 재검토 대상에 포함.
- 자동 분석 사용 중지: `config.local.json`에 `speakerReview: false` 설정 후 JC-LIVE 정상 재시작. 원문과 기존 결과 유지.
- 수동 이름 복구: 관리자 되돌리기 사용. `speaker_decision_history`와 `review_state`에 변경 이력 보존. 전체 DB 복구 전 서비스 중지와 별도 현재 DB 백업 필요.
- 운영 적용 전 `scripts/backup-db.mjs config.local.json 365`로 백업·무결성 검사. 백업 DB의 명단·수동 확인 이력·원음을 Git에 추가하지 않음.
