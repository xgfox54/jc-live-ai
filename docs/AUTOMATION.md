# 공식 생방송 자동 등록과 회의록

## 수집 대상

| 구분 | 공식 주소 |
|---|---|
| YouTube 생방송 채널 | https://www.youtube.com/channel/UChRn5ybNcNv55_x9QGW-xXg/streams |
| 오늘의 생방송 | https://www.council.jeju.kr/broadcast/index.do |
| 생방송 일정 | https://www.council.jeju.kr/broadcast/schedule.do |

서버 시작 시 신규 주소 탐색 기본 활성화. SQLite에 저장한 관리자 설정 우선 적용. 기본 확인 간격 30초이며 조회 지연·차단 시 실제 확인 간격 증가. 각 수집 대상의 조회와 등록을 독립 처리.

YouTube는 공식 채널의 생방송·예약 항목만 조회. 홈페이지는 공식 생방송 상세 링크만 등록. 종료 표시 항목과 다시보기 목록 제외. 일정만 있고 영상 상세 주소가 없는 회의는 주소 공개 이후 등록. 홈페이지 상세 페이지의 일시·회차·회의 구분·소관·심의 안건 수집.

## 등록·수집

1. 새 주소 발견 후 방송 목록 저장.
2. YouTube 영상 식별값과 공식 상세 주소로 중복 제거. 나중에 같은 영상으로 확인된 항목의 세션·회의록도 통합.
3. 사용 가능한 슬롯에 자동 등록. 최대 8개, 생방송 우선 배치. 부족하면 대기.
4. 예약 방송은 시작 대기. 실제 생방송 상태 확인 후 원음 저장과 전사 시작.
5. 음원 수집 종료 후 남은 전사 처리. 방송별 회의록 저장, 자동 등록 슬롯 재사용.

관리자가 등록한 슬롯과 수집 중인 슬롯은 자동 덮어쓰기 제외. 자동 등록된 예약 대기 슬롯은 새 생방송에 우선 배정 가능하며 원래 예약 항목은 대기 목록 유지. 재시작·슬롯 재사용 이후에도 방송별 기록 보존.

관리자 화면의 ‘신규 방송 자동 등록’에서 탐색 상태·대상별 조회 결과·대기 목록 확인. ‘신규 주소 탐색 끄기’는 새 주소 등록만 중지. 이미 등록된 방송의 감지·수집은 계속 동작. 방송별 ‘수집 중지’는 해당 방송의 자동 감지도 해제. 명시적으로 감지를 다시 켜기 전까지 재등록으로 수집을 재개하지 않도록 중지 상태 보존.

## 방송 시작 부분과 복구

YouTube는 yt-dlp의 --live-from-start 옵션으로 시작 부분 수집 요청. 홈페이지의 HLS 방송은 현재 보관된 가장 이른 구간부터 수집 요청. 조회 간격, 서버 중단, 제공자의 보관 범위·다시보기 설정 때문에 방송 첫 순간부터 전체 녹음을 보장하지 않음.

시작 부분의 음원 수집 연결에 실패하면 누락 기록을 남기고 다음 확인 때 현재 시점 수집으로 재시도. 이 전환도 회의록에 표시. 저장 공간 오류·세션별 녹음 한도 도달은 자동 재시도 중단 사유. 관리자 조치 후 자동 감지 재활성화 필요.

방송 종료가 감지돼도 시작 부분 수집의 남은 음원은 처리 지속. 수동 중지·서버 종료 시 다운로드 도구의 하위 프로세스까지 정리. 서버·PC가 꺼진 동안의 방송은 감지 불가.

옵션의 제공자 지원 범위: [yt-dlp 공식 문서](https://github.com/yt-dlp/yt-dlp#general-options).

## 회의록 구성과 저장

외부 생성형 AI API 추가 없이 로컬 음성 인식 결과에서 발언을 발췌하는 방식. 별도 API 키·외부 요약 API 비용 없음. 추출 기준에 따라 주요 논의 최대 20개, 의결 관련·후속 조치 관련 발언 각각 최대 100개 표시. 전체 전사문에는 해당 제한 미적용.

| 항목 | 내용 |
|---|---|
| 회의 정보 | 공식 페이지에서 확인한 일정·소관·안건·출처 |
| 주요 논의 | 전사문에서 대표 발언 발췌 |
| 의결 관련 발언 | 의결 표현이 포함된 발언 발췌, 정식 의결 결과 확정 아님 |
| 요청·후속 조치 | 요청 표현이 포함된 발언 발췌 |
| 전체 전사문 | 수정문 우선, 세션·입력 구간·경과 시각 포함 |
| 수집 범위 | 시작 부분 요청 여부, 오류·누락·재시작 안내 |

최대 10초 간격 갱신, 서버 정상 종료 시 최종 갱신. 작성 중과 검토용 초안 구분. 발언자·참석자·표결 수치를 추정해 채우지 않음. 원음·공식 기록을 통한 검토 필요. 전사문 수정은 다음 회의록 갱신에 반영.

SQLite에 회의록 저장, data/minutes/에 방송별 Markdown·JSON 파일 저장. minutesDirectory 설정으로 파일 경로 변경 가능. 파일 저장 오류는 관리자 화면에 표시. data/ 전체와 실행 설정 백업 필요.

이용자 [회의록 화면](http://127.0.0.1:4320/minutes)에서 열람·내려받기. 관리자 접근키 입력 불필요. 기존 이용자 화면의 8개 방송 선택·최대 2개 동시 시청 유지.
